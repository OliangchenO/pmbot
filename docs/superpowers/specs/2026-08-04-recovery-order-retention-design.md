# 补单订单保留设计

## 目标

未配对库存的互补补单以配平成交为优先，不因普通做市刷新而频繁撤挂，从而保留订单簿队列位置。

## 规则

补单订单挂出后保持原价和剩余数量。普通盘口、微小价格漂移、流量偏移和普通双边做市刷新不得撤换该订单。

仅允许以下安全事件撤换补单：

1. 成交或仓位快照使净敞口数量变化；新订单数量等于新的净敞口。
2. 订单在交易所消失、被取消或被拒绝。
3. GTD 临近到期，需在到期前续单。
4. 原价格不再满足配对成本硬上限；先撤销，再以不高于新上限的价格重挂。

## 边界

- 本规则仅适用于存在 `abs(unpaired) >= MIN_TAKER_SHARES` 的互补补单。
- 未配平时不恢复普通双边做市；配平后恢复原有普通报价刷新策略。
- 不改变强制 FAK 对冲、被动退出、合并或实时订单对账路径。

## 验收

- 相同敞口、价格仍在成本上限内、未临近到期时，盘口变化不会调用取消或替换补单。
- 敞口由 68 变为 58 时，旧补单被替换为 58 股。
- 成本上限收紧至低于现有补单价格时，旧单被撤销并以受限价格重新提交。
- GTD 续单仍遵循现有“先挂后撤”的安全顺序。
